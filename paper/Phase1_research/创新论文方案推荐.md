# 创新论文方案推荐：基于 UR + Franka 的柔顺控制（导纳/阻抗）统一接口

> **硬件条件**：UR 机械臂 + Franka 机械臂
>
> **研究范围**：现阶段聚焦于**导纳/阻抗控制（柔顺控制）算法的统一**，设计一套过渡对接方案，将不同机械臂的底层柔顺控制统一到一套 API 接口上，使后续其他机械臂也能快速接入。
>
> **整理日期**：2026-07-24（修订版）
>
> **核心挑战**：Franka 原生支持力矩级控制（1kHz，阻抗控制），UR 原生支持位置/速度级控制（500Hz，导纳控制 + force mode），两者的控制因果性不同，需要在统一接口中弥合这一差异。

## 1. 核心问题分析

### 1.1 阻抗控制 vs 导纳控制：因果性差异

| 维度 | 阻抗控制（Impedance） | 导纳控制（Admittance） |
|------|----------------------|----------------------|
| **输入** | 位置误差（测量运动） | 外力（力传感器测量） |
| **输出** | 关节力矩（命令力） | 期望位置/速度（命令运动） |
| **适用硬件** | 力矩可控机器人（Franka、KUKA iiwa） | 位置可控机器人（UR、工业机器人） |
| **控制频率** | ≥1kHz（力矩环） | 100-500Hz（位置环） |
| **环境刚度适应性** | 适合柔顺环境 | 适合刚性环境 |
| **稳定性** | 与刚性环境接触可能不稳定 | 与柔性环境交互可能不稳定 |

### 1.2 Franka 与 UR 的控制接口差异

| 维度 | Franka Emika (Panda/FR3) | Universal Robots (UR5e/UR10e/UR16e) |
|------|--------------------------|--------------------------------------|
| **底层接口** | libfranka / FCI（C++，UDP 1kHz） | ur_rtde / RTDE（C++/Python，500Hz） |
| **力矩控制** | ✅ 原生支持（关节力矩直接命令） | ❌ 不直接支持（仅通过 force mode 间接） |
| **位置控制** | ✅ 支持（内部阻抗模式） | ✅ 原生支持（servoj/movel） |
| **力传感** | 关节力矩传感器（本体感知） + 可选末端 F/T | 内置末端力/力矩估计 + 可选外部 F/T |
| **内置阻抗模式** | 笛卡尔阻抗、关节阻抗 | force mode（力/位混合，参数有限） |
| **实时性** | 硬实时（PREEMPT_RT，1kHz） | 软实时（500Hz，无硬实时保证） |
| **控制粒度** | 全关节力矩级 | 速度/位置级 + force mode 配置 |

### 1.3 统一的核心难点

```
                 统一柔顺控制 API
                      │
         ┌────────────┴────────────┐
         │                         │
    阻抗控制路径                导纳控制路径
   (Franka: 力矩级)          (UR: 位置级)
         │                         │
  测量位置误差 → 计算力矩    测量外力 → 计算期望位移
         │                         │
  τ = Jᵀ(K·Δx + D·Δẋ)      x_d = x_ref + admittance(F_ext)
         │                         │
    发送关节力矩             发送关节位置/速度
```

**关键矛盾**：同一套 API 需要根据目标硬件的能力自动选择阻抗或导纳路径，且两条路径在用户看来行为一致。

## 方案 A：混合阻抗-导纳控制统一框架（HIAC）

### 论文信息

- **标题**：Hybrid impedance and admittance control for optimal robot–environment interaction
- **作者**：Dexi Ye, Chenguang Yang, Yiming Jiang, Hui Zhang
- **年份**：2024
- **期刊**：Robotica (Cambridge University Press)
- **链接**：https://doi.org/10.1017/S0263574723001601
- **验证平台**：2-DOF 仿真 + 7-DOF Franka Emika Panda

### 核心思想

阻抗控制和导纳控制具有**互补的因果结构**：阻抗控制在刚性环境中可能不稳定，导纳控制在柔性环境中可能不稳定。本文提出混合阻抗-导纳控制（HIAC）方案，通过**切换控制器和占空比调节**，在两种控制范式之间生成一系列中间控制器，实现全环境刚度范围内的最优交互性能。

### 关键技术

1. **二阶目标阻抗模型**：通过带虚拟惯性的阻抗自适应方法，无需精确环境动力学和加速度反馈
2. **混合系统框架**：使用切换控制器和占空比调节，在阻抗和导纳响应之间插值
3. **最优占空比映射**：根据环境特性自动选择最优中间控制器
4. **稳定性保证**：确保系统在整个切换过程中的稳定性

### 与你目标的契合点

**这是最直接相关的方案**——你的核心问题正是"Franka 适合阻抗控制、UR 适合导纳控制，如何统一"。HIAC 提供了理论框架：

```
统一柔顺控制 API
    │
    ├── if 目标机器人支持力矩控制 (Franka):
    │     └── 阻抗控制路径 (占空比 = 0)
    │
    ├── if 目标机器人仅支持位置控制 (UR):
    │     └── 导纳控制路径 (占空比 = 1)
    │
    └── if 目标机器人支持混合模式:
          └── HIAC 混合路径 (占空比 ∈ (0,1))
              → 根据环境刚度自适应调节
```

### 你的复现方案

1. 在 Franka 上实现 HIAC 的阻抗控制路径（利用 libfranka 力矩接口）
2. 在 UR 上实现 HIAC 的导纳控制路径（利用 ur_rtde 位置接口 + 力传感器）
3. 设计统一 API 封装，根据硬件能力自动选择路径
4. 在两台机械臂上执行同一柔顺控制任务（如接触表面滑动），对比行为一致性
5. 验证混合模式在 Franka 上的效果（Franka 也可以模拟导纳控制）

### 创新拓展方向

- **硬件能力自适应**：扩展 HIAC 的占空比概念——不是根据环境刚度切换，而是根据**硬件控制能力**切换阻抗/导纳路径
- **跨机器人行为一致性度量**：定义量化指标，衡量同一 API 在不同机械臂上的柔顺行为一致性
- **结合你的多传感器数据集**：利用力/触觉传感器数据在线估计环境刚度，自动调节占空比

### 注意事项

- 原论文仅在 Franka 上验证，UR 的适配需要自行实现
- 占空比切换的平滑性需要仔细调试，避免切换抖动

## 方案 B：SE(3) 几何统一力-阻抗控制（GUFIC）

### 论文信息

- **标题**：Geometric Formulation of Unified Force-Impedance Control on SE(3) for Robotic Manipulators
- **作者**：Joohwan Seo, Nikhil P. S. Prakash, Soomi Lee, Arvind Kruthiventy, Megan Teng, Jongeun Choi, Roberto Horowitz
- **年份**：2025（提交至 CDC 2025）
- **机构**：UC Berkeley + 香港建造机器人中心 + 延世大学
- **链接**：https://arxiv.org/abs/2504.17080
- **代码**：https://github.com/Joohwan-Seo/GUFIC_mujoco

### 基础论文

- **UFIC（统一力-阻抗控制）**：Haddadin & Shahriari, IJRR 2024
  - 链接：https://doi.org/10.1177/02783649241249194
  - 将阻抗控制与力控制统一，基于能量tank保证无源性和稳定性
  - 适用于刚性关节和柔性关节机器人

### 核心思想

在 SE(3) 流形上统一表述力控制和阻抗控制，利用**能量tank机制**保证系统无源性（Passivity），同时实现轨迹跟踪和力跟踪。GUFIC 继承了 GIC 的 SE(3) 等变性，使得控制律在任意坐标系变换下保持不变——**这意味着同一控制律可以直接部署到不同安装方向、不同基坐标系的机械臂上**。

### 关键技术

1. **SE(3) 流形上的统一控制律**：将位置和旋转统一在李群上处理，避免欧拉角奇异性
2. **能量tank无源性保证**：分离的力控tank和阻抗tank，确保与任意无源环境交互的安全性
3. **速度场和力场**：解决 UFIC 的非因果实现问题
4. **SE(3) 等变性**：控制律在坐标变换下不变，天然支持跨机器人迁移

### 与你目标的契合点

GUFIC 提供了统一柔顺控制的**数学理论基础**：

- SE(3) 等变性 → 同一控制律在不同机械臂（不同基坐标系）上行为一致
- 能量tank → 保证不同硬件平台上柔顺控制的安全性
- 统一力-阻抗 → 不需要区分"力控"还是"位控"，一个框架涵盖两者

### 你的复现方案

1. 基于 GUFIC 开源代码（MuJoCo 仿真）理解控制律实现
2. 将 GUFIC 控制律适配到 Franka（libfranka 力矩接口，直接实现）
3. 将 GUFIC 控制律适配到 UR（需要解决 UR 无直接力矩控制的问题）：
   - 方案一：在 UR 上使用导纳控制近似实现 GUFIC 的阻抗部分
   - 方案二：利用 UR 的 force mode 实现 GUFIC 的力跟踪部分
   - 方案三：使用动力学模型计算所需力矩，转换为等效位置命令
4. 验证 SE(3) 等变性：将 Franka 和 UR 安装在不同方向，执行同一柔顺任务
5. 对比实验：GUFIC vs 传统笛卡尔阻抗控制在跨机器人迁移时的性能差异

### 创新拓展方向

- **跨硬件力矩-位置适配层**：GUFIC 假设力矩控制可用，你可以设计一个适配层，当力矩控制不可用时（如 UR），自动将 GUFIC 的力矩输出转换为位置命令（通过逆动力学）
- **GUFIC + HIAC 结合**：在 GUFIC 的理论框架下，用 HIAC 的混合切换策略处理 Franka（力矩）和 UR（位置）的硬件差异
- **学习增强**：利用你的多传感器数据集学习 GUFIC 的速度场和力场，实现环境自适应

### 注意事项

- GUFIC 目前仅在仿真中验证，真机实现需要大量工程工作
- 李群/李代数数学门槛较高
- UR 上无法直接实现力矩控制，需要近似方案

## 方案 C：CRISP 机器人无关柔顺控制器

### 论文信息

- **标题**：CRISP — Compliant ROS2 Controllers for Learning-Based Manipulation Policies and Teleoperation
- **作者**：Daniel San José Pro, Oliver Hausdörfer, Ralf Römer, Maximilian Dösch, Martin Schuck, Angela P. Schoellig
- **年份**：2025（arXiv，2025年9月提交，2026年2月修订）
- **机构**：多伦多大学航空航天研究所（UTIAS）
- **链接**：https://arxiv.org/abs/2509.06819
- **代码**：https://github.com/utiasDSL/crisp_controllers
- **文档**：https://utiasDSL.github.io/crisp_controllers

### 核心思想

CRISP 是一套轻量级 C++ 实现的柔顺控制器，兼容 ROS2 control 标准，支持**任何提供关节力矩接口的机械臂**。提供笛卡尔阻抗控制和操作空间控制，专为高层学习策略和遥操作设计。

### 关键技术

1. **机器人无关设计**：通过 ros2_control 的 effort 接口，兼容任何支持力矩控制的机械臂
2. **笛卡尔阻抗控制**：C++ 实时实现（1kHz），支持在线参数调节（刚度、阻尼）
3. **操作空间控制（OSC）**：支持任务空间动力学解耦
4. **Python 接口（CRISP_PY）**：简化 ROS2 操作，无需处理 topic/spin 等
5. **Gymnasium 接口（CRISP_GYM）**：统一的数据采集和策略部署流水线

### 已验证平台

- **真机**：Franka Robotics FR3
- **仿真**：Kuka IIWA14、Kinova Gen3

### 与你目标的契合点

CRISP 是目前最接近你目标的**工程基座**：

```
你的统一柔顺控制 API
    │
    ├── 控制律层：可基于 CRISP 的阻抗/OSC 控制器
    │
    ├── 硬件适配层：
    │     ├── Franka → ros2_control effort 接口（CRISP 原生支持）
    │     └── UR → 需要扩展（UR 的 ros2_control 默认不支持 effort）
    │
    └── 用户接口层：CRISP_PY 的 Python 接口
```

**关键差距**：CRISP 要求机械臂提供力矩接口，UR 默认不满足。这正是你可以创新的点——设计一个 UR 的力矩-位置适配层，使 UR 也能接入 CRISP 框架。

### 你的复现方案

1. 安装 CRISP 并在 Franka FR3 上验证笛卡尔阻抗控制
2. 分析 CRISP 的控制器接口设计（effort 接口要求）
3. 为 UR 设计适配层：
   - 在 UR 上通过 ur_rtde 获取关节状态和力矩估计
   - 将 CRISP 输出的期望力矩转换为 UR 可执行的位置/速度命令
   - 使用 UR 的 force mode 处理力跟踪部分
4. 在 UR 上部署适配后的 CRISP 控制器
5. 对比 Franka（原生 CRISP）和 UR（适配 CRISP）的柔顺控制性能

### 创新拓展方向

- **力矩-位置桥接适配器**：设计通用的适配层，将基于力矩的柔顺控制律适配到仅支持位置控制的机器人
- **控制模式自动协商**：统一 API 自动检测硬件能力，选择最优控制路径
- **性能损失量化**：量化位置控制机器人（UR）执行力矩级柔顺控制时的性能损失

### 注意事项

- CRISP 强依赖 ROS2 生态，如果你的目标是中间件无关的方案，需要提取核心控制算法
- UR 的 ros2_control 硬件接口（ur_robot_driver）目前主要支持位置控制，力矩控制需要额外开发

## 方案 D：交互式力-阻抗控制（IFIC）

### 论文信息

- **标题**：Interactive Force-Impedance Control
- **作者**：Fan Shao, Satoshi Endo, Sandra Hirche, Fanny Ficuciello
- **年份**：2025
- **机构**：那不勒斯大学（PRISMA Lab）+ 慕尼黑工业大学（ITR）
- **链接**：https://arxiv.org/abs/2510.17341

### 核心思想

提出统一的交互式力-阻抗控制（IFIC）框架，在 port-Hamiltonian 框架内同时处理交互力控制和阻抗控制，通过**交互功率流自适应**实现接触密集型环境中的安全柔顺交互。解决了统一力-阻抗控制在与非无源环境交互时的无源性问题。

### 关键技术

1. **Port-Hamiltonian 框架**：将机器人建模为端口系统，交互端口和任务控制端口分离
2. **交互功率流自适应**：根据交互功率流的方向和大小自适应调节控制行为
3. **能量tank增强**：保证与非无源环境交互时的系统无源性
4. **角色自适应**：机器人在主动领导者（力控）和被动跟随者（阻抗）之间灵活切换

### 与你目标的契合点

IFIC 解决了统一柔顺控制中的**安全性核心问题**：

- 当 Franka（力矩控制）和 UR（位置控制）执行同一柔顺任务时，与环境的交互安全性需要统一保证
- IFIC 的 port-Hamiltonian 框架不依赖具体控制实现方式（力矩 or 位置），只关注能量流
- 这为你的统一 API 提供了**安全抽象层**的理论基础

### 你的复现方案

1. 理解 IFIC 的 port-Hamiltonian 建模方法
2. 将 Franka 和 UR 分别建模为 port-Hamiltonian 系统
3. 设计统一的交互端口接口，使两台机械臂的能量流管理一致
4. 在两台机械臂上执行同一接触任务（如擦拭表面），验证安全性一致性
5. 对比有/无 IFIC 安全框架的碰撞安全性

### 创新拓展方向

- **跨硬件无源性统一**：设计统一的能量tank管理策略，不依赖具体硬件的控制模式
- **多机器人协同柔顺**：Franka 和 UR 协同操作同一物体时的无源性保证
- **结合你的力/触觉数据**：利用多传感器数据更准确地估计交互功率流

## 方案 E：安全变阻抗控制强化学习（C-GMS）

### 论文信息

- **标题**：Safe and Optimal Variable Impedance Control via Certified Reinforcement Learning
- **作者**：Shreyas Kumar, Ravi Prakash
- **年份**：2025（ICRA 2026 接收）
- **机构**：印度科学理工学院（IISc Bangalore）
- **链接**：https://arxiv.org/abs/2511.16330

### 核心思想

将变阻抗控制（VIC）与强化学习结合，提出 Certified Gaussian-Manifold Sampling（C-GMS）框架，通过在稳定增益调度的流形上采样，**保证每次策略rollout都是稳定的且物理可实现的**，无需奖励惩罚或事后验证。

### 关键技术

1. **DMP + VIC 联合学习**：同时学习运动轨迹和时变阻抗增益
2. **Lyapunov 稳定性保证**：策略探索被限制在稳定流形上
3. **执行器可行性约束**：确保增益在物理执行器限制内
4. **有界跟踪误差保证**：在有界模型误差和不确定性下保证有界跟踪误差

### 与你目标的契合点

- 提供了变阻抗控制参数自动调优的方法，可用于统一 API 的参数自适应
- 稳定性保证机制可以确保统一 API 在不同硬件上的安全部署
- 但主要面向力矩控制机器人，UR 需要适配

**关键代码片段（libfranka 笛卡尔阻抗控制核心）**：
```cpp
// 控制频率：1kHz
// 核心回调函数
franka::Torques control_callback(const franka::RobotState& state,
                                  franka::Duration period) {
    // 1. 计算笛卡尔误差（位姿偏差）
    Eigen::Vector6d error = computePoseError(state.O_T_EE, desired_pose);
    
    // 2. 阻抗控制律：F = K * Δx + D * Δẋ
    Eigen::Vector6d F_desired = stiffness_ * error + damping_ * velocity_error;
    
    // 3. 转换为关节力矩：τ = Jᵀ * F
    Eigen::VectorXd tau_d = jacobian.transpose() * F_desired;
    
    // 4. 补偿重力和科里奥利力
    tau_d += coriolis + gravity;
    
    return tau_d;  // 直接发送关节力矩
}
```

**关键代码片段（ur_rtde 导纳控制核心）**：
```python
# 控制频率：~500Hz (RTDE)
# 核心循环
while running:
    # 1. 读取末端力/力矩（内置或外部传感器）
    F_ext = rtde_receive.getActualTCPPose()  # 或从 F/T 传感器读取
    
    # 2. 导纳控制律：M·ẍ + D·ẋ + K·x = F_ext
    #    数值积分求解期望位移
    delta_x_ddot = M_inv * (F_ext - D * delta_x_dot - K * delta_x)
    delta_x_dot += delta_x_ddot * dt
    delta_x += delta_x_dot * dt
    
    # 3. 计算期望位姿
    desired_pose = equilibrium_pose + delta_x
    
    # 4. 逆运动学 → 关节角度
    desired_q = inverse_kinematics(desired_pose)
    
    # 5. 发送关节位置命令
    rtde_control.servoj(desired_q, velocity=0.5, acceleration=0.5)
    
    rtde_control.waitPeriod(dt)  # 保持 500Hz
```

### UR 与 Franka 的关键工程差异总结

| 工程维度 | Franka (libfranka) | UR (ur_rtde) | 统一策略 |
|---------|-------------------|-------------|---------|
| 控制回调 | 1kHz 闭环保证，超时急停 | 500Hz 最佳努力，无超时保护 | 统一 API 适配不同频率 |
| 命令类型 | 关节力矩（N·m） | 关节位置（rad）/速度 | API 层抽象为"控制模式" |
| 力感知 | 关节力矩传感器（1kHz） | 末端力估计（~500Hz） | 统一为末端 wrench 接口 |
| 安全机制 | 硬件级碰撞检测 + 急停 | 软件级安全停止 + 力限制 | 统一安全抽象层 |
| 阻抗参数 | setCartesianImpedance() | 无原生支持，需自定义 | 统一参数配置接口 |

### 论文定位

**推荐定位**：IEEE RA-L（Robotics and Automation Letters）系统论文

- 审稿周期短（平均 3 个月）
- 接受系统类论文，要求真实硬件实验
- 影响因子适中，机器人领域认可度高

### 核心创新点（4个）

1. **硬件自适应的阻抗-导纳混合切换**：根据机械臂控制能力（力矩 vs 位置）自动选择最优柔顺控制路径，而非仅根据环境刚度切换
2. **SE(3) 等变的统一控制律**：保证同一控制律在不同基坐标系、不同安装方向的机械臂上行为一致
3. **跨硬件无源性统一保证**：不依赖具体控制实现方式（力矩 or 位置）的安全抽象层
4. **可扩展的统一 API 设计**：仅需配置物理参数（DH 参数、质量分布、控制频率）即可接入新机械臂

   - 5.1 Franka 适配器（力矩路径）
   - 5.2 UR 适配器（位置路径 + force mode）
6. **Experiments**：
   - 6.1 实验设置（Franka + UR + 力传感器）
   - 6.2 行为一致性验证（同一任务两台机械臂）

   - 6.4 与现有方法对比（CRISP、ros_control）

8. **Conclusion**
