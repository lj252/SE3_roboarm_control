## 1. 统一控制接口与硬件抽象层（HAL）

### 1.1 One Interface, Many Robots: Unified Real-Time Low-Level Motion Planning for Collaborative Arms

- **作者**：WinGs Operating Studio 团队
- **年份**：2026
- **来源**：arXiv:2604.08787
- **链接**：https://arxiv.org/abs/2604.08787
- **摘要**：提出了一种用于协作机械臂实时底层运动规划的通用接口。基于 WinGs Operating Studio (WOS) 中间件，将多样化的机器人组件抽象为统一的软件资源，并提供语言无关的 API。通过 n 次多项式插值器和二次规划求解器生成平滑、连续可微的轨迹，具有精确的位置、速度和加速度曲线。在三个场景中验证：离线绘图、低频率重规划抓取动态目标、遥操作实验。
- **相关性**：★★★★★ 直接针对异构机械臂的统一底层运动控制接口，与本研究目标高度一致。

### 1.2 Control Your Robot: A Unified System for Robot Control and Policy Deployment

- **来源**：论文评述（themoonlight.io）
- **链接**：https://www.themoonlight.io/tw/review/control-your-robot-a-unified-system-for-robot-control-and-policy-deployment
- **摘要**：将机器人系统分解为基本单元：控制器、传感器和数据处理模块，每个单元暴露可配置和可调用的接口。通过定义一组最小化的统一 API，开发者只需为每个硬件平台实现一次接口，抽象掉设备特定的通信协议，显著降低跨平台集成成本。在单臂（Dr ALOHA + AigleX piper）和双臂（Y1 ALOHA）系统上进行了验证。
- **相关性**：★★★★★ 提出了模块化接口统一方案，流程标准化（数据采集→预处理→模型微调→推理部署），与本研究方向高度吻合。

### 1.3 A Modular Robot Arm Control Stack (Franka-Interface & FrankaPy)

- **作者**：卡内基梅隆大学机器人研究所（智能自主操作实验室）
- **年份**：2020
- **来源**：arXiv:2011.02398v1
- **链接**：https://www.pnprobotics.com/nd.jsp?id=38
- **摘要**：设计了一个模块化的机器人控制堆栈，为 Franka 科研机器人提供可定制和可访问的接口。将高级机器人控制命令抽象为"技能"，并分解为轨迹生成器、反馈控制器和终止处理程序的组合。底层控制在 C++ 中实现并以 1 kHz 运行，高级命令在 Python 中公开。外部传感器反馈可实时传输到低级控制器。
- **相关性**：★★★★☆ 展示了模块化控制堆栈的设计范式，对抽象层设计有重要参考价值。

### 1.4 XBot: A Cross-Robot Software Framework for Real-Time Control

- **作者**：L. Muratore, A. Laurenzi, N. Tsagarakis
- **年份**：2021
- **来源**：IntechOpen, DOI: 10.5772/INTECHOPEN.97066
- **链接**：https://xueshu.baidu.com/usercenter/paper/show?paperid=1y7h0p30913q0240x96d0ph01d194781
- **摘要**：引入 XBot 软件架构，能够在相对较高的控制频率下以最小抖动实现实时（RT）性能，同时具有增强的灵活性和抽象特性。关键特性是跨机器人兼容性——基于配置文件即可在不同机器人上使用框架而无需修改代码。通过名为 XBotInterface 的机器人无关 API，确保与 ROS、YARP、OROCOS 等工具的互操作性。已在 KUKA LBR iiwa/lwr 4+、Franka Emika Panda、人形机器人 WALK-MAN/COMAN+、四足半人马机器人 CENTAURO 上验证。
- **相关性**：★★★★★ 直接提出了跨机器人实时控制框架，已在多种机械臂上验证，是本研究最重要的参考文献之一。

### 1.5 ROS End-Effector: A Hardware-Agnostic Software and Control Framework

- **期刊**：Journal of Intelligent & Robotic Systems, Vol. 108, Issue 4
- **出版社**：Springer
- **DOI**：10.1007/s10846-023-01911-5
- **链接**：https://www.peeref.com/zh/works/28501443
- **摘要**：开源框架，为不同类型的机器人末端执行器提供统一的控制和集成方案。自动提取末端执行器的功能并屏蔽物理硬件差异，允许使用一组自动提取的高级抓取原语控制末端执行器。利用硬件无关的软件模块（包括 HAL、API、仿真工具和 GUI），有效促进多样化末端执行器设备的集成。
- **相关性**：★★★★☆ 虽然聚焦于末端执行器，但其硬件无关的设计理念与本研究中统一机械臂控制的思路一致。

### 1.6 Unified Interface for Industrial Robots (Franka & UR5e Skill Transfer)

- **链接**：https://github.com/wxl97/Skill-transfer-between-Franka-and-UR5e
- **摘要**：开源项目，为 Franka Emika Panda 和 UR5e 提供统一接口。通过 ROS 框架自动启动适当的 bringup（驱动程序 + MoveIt），等待节点初始化后执行选定的任务计划。使用 JSON 定义高级任务及其所需的技能序列，配合全局知识库检查能力兼容性。
- **相关性**：★★★★★ 直接实现了 Franka 和 UR5e 之间的统一控制接口，是本研究最直接的工程参考。

### 1.7 ARM/HAL: Hardware Abstraction Layer for Robotic Arms

- **链接**：https://github.com/Slugbotics/ARM/tree/main/HALs
- **摘要**：开源 HAL 实现，允许主控制代码使用相同的方法集与不同硬件平台（物理机械臂、仿真器、远程机械臂）交互。所有 HAL 继承自 HAL_base，定义了关节控制、相机访问和夹爪操作的必需接口。支持 CoppeliaSim 仿真、物理硬件、远程 HTTP API 等多种后端。
- **相关性**：★★★★☆ 提供了完整的 HAL 抽象基类设计范例，对新接口设计有直接参考价值。

### 1.8 Fraunhofer Italia Manipulator Control Stack

- **作者**：Marco Magri（Fraunhofer Italia）
- **年份**：2023-2024
- **链接**：https://community.qtorque.io/FraunhoferItalia/fhi_manipulator_control_stack
- **摘要**：用于模块化和可重构机器人控制器开发和实现的框架。将低级控制器逻辑与硬件特定实现（如 ROS 2 Control 或 XBot2）解耦，提供灵活性和可扩展性。包含机器人动力学库（处理正/逆运动学、雅可比矩阵和动力学方程）和机械臂控制库（标准化低级控制器逻辑）。支持多种框架，确保跨平台一致的控制逻辑实现。
- **相关性**：★★★★☆ 专注于模块化和可重构机器人的控制框架，解耦设计理念与本研究一致。

## 2. 机器人中间件与控制框架

### 2.1 ros_control: A Generic and Simple Control Framework for ROS

- **作者**：Sachin Chitta, Wim Meussen, Vijay Pradeep, Eitan Marder-Epstein
- **年份**：2017
- **期刊**：Journal of Open Source Software, 2(20), 456
- **DOI**：10.21105/joss.00456
- **链接**：https://www.theoj.org/joss-papers/joss.00456/10.21105.joss.00456.pdf
- **摘要**：框架的骨干是硬件抽象层（HAL），作为不同仿真和真实机器人之间的桥梁。通过 `hardware_interface::RobotHW` 类提供抽象，特定机器人实现继承该类。定义了只读或读写的类型化关节和执行器接口（状态、位置、速度和力接口），使控制器与硬件无关。已在 NASA Valkyrie/Robonaut、PAL Robotics TIAGo/TALOS、Shadow Hand、Universal Robots UR3/UR5 等平台上应用。
- **相关性**：★★★★★ ROS 生态中最核心的控制框架，其 HAL 设计是统一接口方案的重要参考。

### 2.2 Robot Operating System 2 (ROS 2): Design, Architecture, and Uses In The Wild

- **作者**：Steve Macenski, Tully Foote, Brian Gerkey, Chris Lalancette, William Woodall
- **年份**：2022
- **期刊**：Science Robotics
- **链接**：https://ar5iv.labs.arxiv.org/html/2211.07752
- **摘要**：ROS 2 基于 DDS（Data Distribution Service）开放标准重新设计，解决了 ROS 1 在安全性、可靠性、非传统环境支持和大规模嵌入式系统方面的局限性。DDS 提供 UDP 传输、分布式发现、内置安全标准。通过五个案例研究展示了 ROS 2 在陆地、海洋、空中和太空领域加速自主系统部署的影响。
- **相关性**：★★★★★ ROS 2 是构建统一控制接口的基础中间件平台，其 DDS 通信架构对实时控制至关重要。

### 2.3 A Survey of Real-Time Support, Analysis, and Advancements in ROS 2

- **年份**：2026
- **来源**：arXiv:2601.10722
- **链接**：https://arxiv.org/abs/2601.10722
- **摘要**：全面综述了分析、增强和扩展 ROS 2 以支持实时执行的研究工作。详细描述了 ROS 2 的内部调度机制和分层架构，包括与 DDS 通信的交互。回顾了单线程和多线程执行器的时间分析、响应时间/反应时间/数据年龄等指标、不同通信模式。讨论了新的执行器算法设计、实时 GPU 管理和通过 micro-ROS 的微控制器支持。
- **相关性**：★★★★☆ 对 ROS 2 实时性能的深入分析，对设计需要实时控制的统一接口有重要参考价值。

### 2.4 From the Desks of ROS Maintainers: A Survey of Modern & Capable Mobile Robotics Algorithms in ROS 2

- **作者**：Steve Macenski, Tom Moore, David Lu, Alexey Merzlyakov, Michael Ferguson
- **年份**：2023
- **期刊**：Robotics and Autonomous Systems
- **来源**：arXiv:2307.15236
- **链接**：https://arxiv.org/abs/2307.15236
- **摘要**：来自 ROS 导航核心维护者的综述，回顾和分析 ROS 2 中移动机器人导航的最新技术。包括在 ROS 1 或其他框架中没有对应的新系统，提供了概述、比较和专家见解。
- **相关性**：★★★☆☆ 虽然聚焦于导航，但 ROS 2 生态系统的整体分析对理解统一接口的生态支撑有参考价值。

### 2.5 Distributed Robotic Systems in the Edge-Cloud Continuum with ROS 2

- **作者**：Jiaqiang Zhang, Farhad Keramat, Xianjia Yu 等
- **年份**：2022
- **来源**：arXiv:2211.00985
- **链接**：https://www.arxiv.org/abs/2211.00985
- **摘要**：回顾了使容器化机器人应用在边缘或云端无缝运行的新架构和技术。涵盖从 ROS 2 工具扩展到 Kubernetes 集成，以及新型仿真器和云仿真如何支持大规模强化学习或分布式联邦学习。
- **相关性**：★★★☆☆ 分布式机器人系统架构对统一接口的云部署和远程控制场景有参考价值。

### 2.6 YARP (Yet Another Robot Platform)

- **维护方**：iCub Facility, Italian Institute of Technology
- **特点**：模块化设计、多线程、多机器松耦合设计模式。支持大量连接类型和操作系统。使用端口发布消息（类似 ROS 中的 topics），通过 yarpserver 连接软件模块。适用于人形机器人。
- **相关性**：★★★☆☆ 作为 ROS 的替代中间件方案，其设计理念对统一接口的跨平台设计有参考价值。

### 2.7 OROCOS (Open Robot Control Software)

- **特点**：包含实时工具包（RTT）、运动学和动力学库（KDL）和贝叶斯滤波库（BFL）。组件化设计，支持 Xenomai 和 PREEMPT_RT 内核补丁实现硬实时执行。端口通信模型在单进程内同步且确定性。
- **相关性**：★★★☆☆ KDL 库已集成到 ROS 中，是机械臂运动学计算的重要工具。硬实时控制设计对底层控制接口有参考价值。

## 3. 跨本体/跨平台技能迁移

### 3.1 Latent Action Diffusion for Cross-Embodiment Manipulation

- **作者**：Erik Bauer, Elvis Nava, Robert K. Katzschmann（ETH Zurich）
- **年份**：2025
- **会议**：ICRA 2026
- **来源**：arXiv:2506.14608
- **链接**：https://srl-ethz.github.io/lad
- **摘要**：通过在潜在动作空间中学习扩散策略来统一不同末端执行器的动作空间。使用对比损失训练编码器，为拟人化机器人手、人手和平行夹爪学习语义对齐的潜在动作空间。通过共同训练来自不同末端执行器的操作数据，使用单一策略实现多机器人控制，操作成功率提高达 13%。
- **相关性**：★★★★☆ 解决了不同末端执行器动作空间异构性问题，对统一控制接口的动作空间抽象有重要参考价值。

### 3.2 Mirage: Cross-Embodiment Zero-Shot Policy Transfer with Cross-Painting

- **作者**：Lawrence Yunliang Chen, Kush Hari 等（UC Berkeley, Google DeepMind）
- **年份**：2024
- **会议**：RSS 2024
- **链接**：http://robot-mirage.github.io/
- **摘要**：研究视觉策略在不同机器人之间的零样本迁移。发现基于状态的笛卡尔控制策略在考虑前向动力学后可以成功零样本迁移到目标机器人。通过"交叉绘画"（cross-painting）技术——在图像中遮罩目标机器人并修复源机器人在相同末端执行器位姿下的图像——实现视觉策略的跨本体迁移。
- **相关性**：★★★★☆ 证明了笛卡尔空间控制策略的跨本体可迁移性，支持统一接口采用笛卡尔空间作为公共控制层的可行性。

### 3.3 CEI: A Unified Interface for Cross-Embodiment Visuomotor Policy Learning

- **作者**：Tong Wu, Shoujie Li 等（清华大学, 南洋理工大学）
- **期刊**：IEEE RA-L
- **链接**：https://cross-embodiment-interface.github.io/
- **摘要**：提出跨本体接口（CEI）框架，实现不同机械臂和末端执行器形态之间的演示数据迁移。引入"功能相似性"概念，使用方向 Chamfer 距离量化，通过梯度优化对齐机器人轨迹，为未见机械臂和末端执行器合成观测和动作。在仿真中将 Franka Panda 的数据/策略迁移到 16 种不同本体，在真实世界实现 UR5+AG95 和 UR5+Xhand 之间的双向迁移，平均迁移率 82.4%。
- **相关性**：★★★★★ 直接提出了跨本体统一接口框架，涵盖数据迁移和策略迁移，与本研究目标高度吻合。

### 3.4 COMPASS: Cross-embodiment Mobility Policy via Residual RL and Skill Synthesis

- **作者**：Wei Liu 等（NVIDIA）
- **年份**：2025
- **来源**：arXiv:2502.16372
- **链接**：https://nvlabs.github.io/COMPASS/
- **摘要**：使用单一本体的专家演示实现可扩展的跨本体移动能力。三阶段工作流：模仿学习预训练→残差强化学习适配→策略蒸馏为单一通用策略。通过本体嵌入向量条件化，显著减少数据收集负担。实现零样本 sim-to-real 迁移，通用策略成功率比预训练 IL 策略高约 5 倍。
- **相关性**：★★★☆☆ 虽然聚焦于移动机器人，但其跨本体策略学习框架对机械臂跨本体控制有借鉴意义。

### 3.5 Open-Teleop: 通用机械手臂示范控制架构

- **来源**：ICT Journal（工研院）
- **链接**：https://ictjournal.itri.org.tw/xcdoc/cont?xsmsid=0M236556470056558161&sid=0P360575078059576161
- **摘要**：提出通用远端操控架构，通过建立远端操控中介层（Teleoperation Bridge），将异质输入统一转译为标准化关节角指令（Joint Command），从根本上解决不同品牌机械臂（如 Universal Robots 使用 RTDE、Techman Robot 使用 Modbus TCP/RTU）的硬件异质性瓶颈。以 TM12 进行实体验证，展示架构在角度追踪精度与即时性上的可行性。
- **相关性**：★★★★★ 直接针对不同品牌机械臂的统一控制中介层设计，与本研究目标完全一致。

## 4. 机器人基础模型与通用策略

### 4.1 Open X-Embodiment: Robotic Learning Datasets and RT-X Models

- **作者**：Open X-Embodiment Collaboration（21 个机构，293+ 作者）
- **年份**：2023
- **来源**：arXiv:2310.08864
- **链接**：https://arxiv.org/abs/2310.08864
- **摘要**：汇集了来自 22 种不同机器人、21 个机构的数据集，展示 527 种技能（160,266 个任务）。证明在多机器人数据上训练的高容量模型（RT-X）表现出正迁移，通过利用其他平台的经验提升多个机器人的能力。提供了标准化数据格式和开源工具，以促进跨本体机器人学习研究。被引用 1422 次。
- **相关性**：★★★★★ 跨本体机器人学习的基础性工作，其标准化数据格式和跨本体训练范式对统一接口设计有深远影响。

### 4.2 RT-2: Vision-Language-Action Models

- **作者**：Google DeepMind
- **年份**：2023
- **参数规模**：55B（基于 PaLI-X）/ 12B（基于 PaLM-E）
- **摘要**：首个真正的 VLA 模型。将预训练的视觉语言模型微调于机器人演示数据，动作表示为文本 token。在新物体上达到 62% 成功率（RT-1 仅 32%），证明互联网规模预训练知识可迁移到物理操作。展现出涌现能力：能推理物体属性、遵循抽象指令、进行思维链推理。
- **相关性**：★★★★☆ 展示了统一动作表示（token化）的可行性，对统一接口的动作空间抽象有启发。

### 4.3 Octo: An Open-Source Generalist Robot Policy

- **作者**：UC Berkeley
- **年份**：2024
- **参数规模**：93M
- **链接**：https://liqing.io/mindflow/Papers/2405-Octo
- **摘要**：在 Open X-Embodiment 800K 轨迹上预训练的 transformer-based diffusion policy。支持任意相机/语言/目标图像输入，能高效微调到新观测/动作空间。采用 ViT 风格 transformer + 块状 attention mask + 可插拔 readout token + diffusion action head。跨 9 个真实机器人 setup（4 个机构）zero-shot 击败 RT-1-X，与 RT-2-X（55B）持平。完全开源（code + checkpoint + data loader）。
- **相关性**：★★★★☆ 展示了通用策略如何通过统一的 token 接口适配不同机器人，其架构设计对统一接口的扩展性有参考价值。

### 4.4 OpenVLA: Open-Source Vision-Language-Action Model

- **作者**：Stanford/Berkeley
- **年份**：2024
- **参数规模**：7B
- **摘要**：基于 Prismatic VLM + LLaMA 2，在 970K Open X-Embodiment 数据上预训练。最易于研究人员微调的开源 VLA，在单个 A100 上推理速度约 5-8 Hz。
- **相关性**：★★★☆☆ 作为开源基础模型，其与统一控制接口的集成方案对实际部署有参考价值。

### 4.5 Pi-zero (Physical Intelligence)

- **年份**：2024
- **参数规模**：3B
- **摘要**：基于流匹配（flow-matching）的动作解码器，优化用于灵巧操作。在双臂和接触丰富任务上表现出色，控制频率高于更大的 VLA 模型。
- **相关性**：★★★☆☆ 展示了高频控制的可行性，对统一接口的实时性要求有参考价值。

### 4.6 Qwen-Robot: 统一动作接口的具身智能模型

- **年份**：2025
- **链接**：https://cdn.watermelonwater.tech/insights/qwenrobot
- **摘要**：通过统一的 80 维状态-动作表示，在单臂、双臂、灵巧手和移动平台之间共享数据。采用相机坐标系下的末端执行器增量位姿动作，使视觉上相似的运动在不同机器人之间数值上也高度接近，从而屏蔽形态差异。上下文策略自适应将执行历史视为隐式本体标识，实现在线行为校准。训练数据超过 38,100 小时，跨 15 个本体。
- **相关性**：★★★★☆ 提出了统一的跨本体动作表示方案，对统一接口的动作空间设计有直接参考价值。

## 5. 仿真环境与基准测试

### 5.1 robosuite: A Modular Simulation Framework and Benchmark for Robot Learning

- **作者**：Yuke Zhu, Josiah Wong, Ajay Mandlekar, Roberto Martín-Martín 等（Stanford, UT Austin, NVIDIA）
- **年份**：2020
- **来源**：arXiv:2009.12293
- **链接**：http://robosuite.ai/
- **摘要**：基于 MuJoCo 物理引擎的模块化仿真框架，提供机器人学习的基准环境。v1.5 版本支持多种机器人本体（包括人形机器人）、自定义机器人组合、复合控制器（包括全身控制器）。核心特性：
  - **机器人抽象层**：同一任务可在 Franka、Sawyer、UR5e、Kinova、IIWA、Jaco、Baxter、ALOHA 上运行，只需一个参数更改
  - **控制器抽象层**：统一 API 暴露关节力矩、关节位置、操作空间和逆运动学控制
  - 9 个标准化任务，密集和稀疏奖励变体
- **相关性**：★★★★★ 其机器人抽象层和控制器抽象层的设计是统一接口方案的最佳实践参考。

### 5.2 manipulator_gym: ManipulatorInterface 抽象基类

- **作者**：Rail-Berkeley（UC Berkeley）
- **链接**：https://deepwiki.com/rail-berkeley/manipulator_gym/2.1-manipulatorinterface
- **摘要**：定义了所有机器人机械臂的标准接口，遵循抽象基类模式。关键设计：
  - **模块化**：透明地交换不同机器人硬件或仿真后端
  - **标准化**：所有机械臂的 API 一致
  - **分布式**：支持机器人和策略代码在不同机器上运行
  - **抽象**：隐藏硬件特定细节
  - 标准动作空间：7维向量 [dx, dy, dz, drx, dry, drz, gripper]
  - 支持 WidowX、ViperX 等多种机器人接口实现
- **相关性**：★★★★★ 提供了完整的统一机械臂接口设计范式，包括客户端-服务端分布式架构，对本研究有直接参考价值。

## 6. 运动学与动力学计算库

### 6.1 Pinocchio: Rigid Body Dynamics Library

- **作者**：Justin Carpentier, Nicolas Mansard 等（INRIA, LAAS-CNRS）
- **年份**：2015-2019
- **来源**：IEEE International Symposium on System Integrations (SII) 2019
- **链接**：https://github.com/stack-of-tasks/pinocchio
- **摘要**：高性能开源刚体动力学计算库，实现：
  - 前向运动学及其解析导数
  - 前向/逆向动力学及其解析导数
  - 质心动力学及其解析导数
  - 雅可比矩阵和 Hessian 计算
  - 基于 Featherstone 算法，支持 CRTP 静态多态、CppAD/CasADi 自动微分、CodeGen 代码生成
  - 7-DOF RNEA 计算约 2μs
- **相关性**：★★★★☆ 作为统一运动学/动力学计算后端的核心库，是构建跨平台控制接口的重要基础设施。

### 6.2 Drake: Model-Based Robotics Toolbox

- **作者**：Toyota Research Institute (TRI) / MIT
- **特点**：全栈机器人工具箱，包含 MultibodyPlant 多体动力学、Lcm 消息传递、自动微分、SceneGraph 碰撞检测。支持 MPC 和轨迹优化。编译较慢（Bazel），但功能全面。
- **相关性**：★★★☆☆ 作为替代的运动学/动力学计算后端，其全栈设计理念对统一接口的计算层选择有参考价值。

### 6.3 KDL (Kinematics and Dynamics Library)

- **来源**：OROCOS 项目，已集成到 ROS
- **特点**：为几何对象、运动链及其运动规范和插值提供类库。支持串行、人形、平行、移动等各种运动链。递归 Newton-Euler 算法，无自动微分。
- **相关性**：★★★☆☆ 作为 ROS 生态中的标准运动学库，是 MoveIt 默认的 IK 求解器之一。

## 7. 品牌特定控制接口

### 7.1 Franka Control Interface (FCI) / libfranka

- **官方文档**：https://www.franka.de/develop/?hsLang=en
- **特点**：
  - 通过以太网连接的外部工作站 PC 进行直接控制
  - 1 kHz 实时控制指令频率
  - 支持五种接口：关节级扭矩指令（含重力与摩擦补偿）、关节位置/速度指令、笛卡尔位姿/速度指令
  - 1 kHz 测量数据：关节位置/速度/扭矩传感器信号、外部力/扭矩估计、碰撞与接触信息
  - 机器人模型库：正运动学、雅可比矩阵、动力学模型、惯性矩阵、科里奥利力与重力矢量
  - C++ 接口 (libfranka)、Python 绑定 (pylibfranka)、ROS/ROS 2 集成
  - MATLAB/Simulink 工具箱（已开源）
- **相关性**：★★★★★ Franka 机器人的底层接口规范，是统一接口需要适配的关键平台之一。

### 7.2 Universal Robots RTDE (Real-Time Data Exchange)

- **官方文档**：https://www.universal-robots.com/articles/ur/interface-communication/real-time-data-exchange-rtde-guide
- **特点**：
  - 实时数据交换接口
  - 支持 URScript 命令发送
  - ur_rtde 第三方库提供高级命令接口
  - ur_robot_driver：官方 ROS 2 驱动
  - ur_ros_rtde：基于 ur_rtde 的新型 ROS 2 驱动，支持插件系统和自定义命令
- **相关性**：★★★★★ UR 机器人的底层接口规范，是统一接口需要适配的另一个关键平台。

### 7.3 ur_ros_rtde: A ROS2 Interface Based on ur_rtde

- **来源**：arXiv:2511.17237
- **链接**：https://arxiv.org/pdf/2511.17237
- **摘要**：提出了一种新型 ROS 2 驱动，与官方 ur_robot_driver 不同，直接暴露高级 URScript 命令，并支持通过插件系统添加自定义命令。比 ur_robot_driver 提供更直接的高级命令访问和更低的开销。
- **相关性**：★★★★☆ 展示了 UR 机器人控制的替代方案，对统一接口的 UR 适配层设计有参考价值。

## 8. 机器人软件架构综述

### 8.1 A Unified Kinematics Modeling, Optimization and Control of Universal Robots

- **作者**：M. Tarokh
- **年份**：2020
- **期刊**：Autonomous Robots, 44, 1233-1248
- **DOI**：10.1007/s10514-020-09929-6
- **链接**：https://babel.isa.uma.es/kipr?p=1262
- **摘要**：开发了适用于广泛自主和非自主机器人的统一运动学建模、优化和控制方法。包括组合两种或多种操作模式的混合机器人（如行走和滚动的组合），以及各种配置的并联机器人。运动方程以嵌入优化准则的紧凑形式推导，用于获得各种有用的运动学形式（递归、本体和肢体末端运动学形式）。
- **相关性**：★★★★☆ 从理论层面提出了统一运动学建模方法，为统一接口的数学基础提供参考。

### 8.2 Hardware Abstraction Layer in Robotics

- **链接**：https://roboticsarchitectureauthority.com/hardware-abstraction-layer-robotics
- **摘要**：系统阐述了机器人 HAL 的定义、范围和工作原理。HAL 的三个功能类别：
  - **传感器抽象**：将 IMU、LiDAR、力/扭矩传感器和相机的原始数据流标准化为类型化、单位一致的数据结构
  - **执行器抽象**：通过命令接口（速度、扭矩、位置设定值）暴露电机控制器、伺服驱动器
  - **通信总线抽象**：包装实时现场总线协议，使上层通过逻辑名称而非总线地址访问关节或外设
  - 工作流程四阶段：初始化→读周期→写周期→错误传播
  - ROS 2 通过 ros2_control 框架正式化 HAL 边界
- **相关性**：★★★★☆ 系统性的 HAL 设计指南，对统一接口的分层架构设计有重要参考价值。

### 8.3 Middleware Selection for Robotics: Evaluation and Tradeoffs

- **链接**：https://roboticsarchitectureauthority.com/middleware-selection-robotics
- **摘要**：对比了主流机器人中间件框架：
  - **ROS 2**（DDS）：分布式发现、QoS 策略、安全标准
  - **LCM**（MIT CSAIL）：UDP 多播、无代理、无保证交付、延迟通常低于 1ms
  - **YARP**（IIT）：端口通信、模块化、多线程
  - **OROCOS**（RTT）：硬实时、Xenomai/PREEMPT_RT、端口同步通信
  - 决策因素：延迟特性、确定性保证、可扩展性、长期可维护性
- **相关性**：★★★☆☆ 中间件选型对统一接口的通信层设计有参考价值。

### 8.4 Software Architectures for Mobile Robots (综述章节)

- **来源**：arXiv:2206.03233v2
- **链接**：https://arxiv.org/pdf/2206.03233v2
- **摘要**：全面对比了 ROS、ROS 2、YARP、OROCOS、Player、CARMEN、MATLAB、MRSD 等机器人软件框架的架构设计和通信机制。
- **相关性**：★★★☆☆ 提供了机器人软件框架的全景对比，有助于理解统一接口的生态定位。

## 9. 研究空白与未来方向

基于以上文献调研，当前研究存在以下空白和机会：

### 9.1 当前研究空白

1. **缺乏面向多品牌机械臂的轻量级统一控制方案**：现有方案（如 ROS 2 Control、XBot）虽然提供了硬件抽象，但依赖完整的 ROS 生态，部署复杂度高。缺乏独立于特定中间件的轻量级统一控制接口。

2. **运动学/动力学参数的自动适配不足**：大多数统一接口方案需要手动配置 URDF 或 YAML 参数，缺乏根据机械臂物理参数（臂长、关节限制、负载能力）自动生成控制参数的机制。

3. **实时性保证的差异化处理**：不同品牌机械臂的实时控制能力差异显著（如 Franka 1kHz 力矩控制 vs UR 的 RTDE 频率限制），现有方案缺乏对这种差异的优雅处理机制。

4. **安全控制的统一抽象缺失**：不同品牌机械臂的安全机制（如 Franka 的碰撞检测、UR 的安全边界）接口不一致，缺乏统一的安全控制抽象层。

5. **从底层控制到高层策略的无缝衔接**：现有工作要么聚焦于底层硬件抽象（ros_control），要么聚焦于高层策略迁移（Open X-Embodiment），缺乏从底层控制到高层策略的完整统一方案。

### 9.2 建议的研究方向

1. **设计中间件无关的统一控制 API**：不依赖 ROS/ROS 2 等特定中间件，提供独立的统一控制接口，支持按需集成到不同生态。

2. **基于物理参数的自适应控制层**：用户只需提供机械臂的物理参数（DH 参数、关节限制、最大速度/加速度），系统自动生成对应的运动学/动力学模型和控制策略。

3. **分层抽象架构**：
   - L0：品牌特定驱动适配层（FCI/libfranka, RTDE/ur_rtde 等）
   - L1：统一硬件抽象层（关节状态/命令接口、安全接口）
   - L2：统一运动学/动力学计算层（基于 Pinocchio/Drake）
   - L3：统一轨迹规划与控制层（位置/速度/力矩/阻抗控制）
   - L4：高级任务接口（技能/动作原语）

4. **实时性自适应机制**：根据目标机械臂的实时控制能力，自动选择最佳控制频率和控制模式。

5. **与基础模型的集成**：设计支持 RT-X、Octo 等通用策略模型的统一动作接口，实现从学习策略到底层控制的无缝衔接。
