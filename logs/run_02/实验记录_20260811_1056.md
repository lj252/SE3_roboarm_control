## 1. 实验目的

按 run_01 的结论（servoJ 级联失稳 → 肘部力矩饱和 + 参考积分漂移 → 发散折叠），把
`--bandwidth 10 → 6` 降低内层负担后重跑同一 circle 任务，验证：
1. 发散/折叠是否消除（指标对照 run_01：积分漂移 RMS、力矩饱和占比、误差发散、折叠特征）；
2. 保护性停止到底发生在**跟踪过程**还是**关机/释放环节**（用 RTDE 全程 `safety_mode` 定位）；
3. 顺便核对模型 FK 坐标系与实机 TCP 是否一致（run_01 时 RTDE 实测 TCP 高度明显低于模型）。

## 4. 实验现象

### Phase0（起步混合，2.00s）— 稳定，同 run_01
误差 0、q_servo−q 全 0、τ=-6.3 Nm（重力保持）远低于限幅。

### Phase2（circle 主阶段，完整跑满 16.00s，未截断）
| 指标 | run_02（bandwidth 6） | run_01（bandwidth 10） | 说明 |
|---|---|---|---|
| 时长 / 周期 | 16.00s / 3659 行 | 7.04s 被截断 | **完整跑满，无保护性停止截断** |
| pos_err 终值 | **0.3 cm** | 62 cm（发散） | 收敛到厘米级 |
| pos_err 峰值 | 10 cm（起步混合阶段） | 发散 | 稳态后 <3 cm |
| rot_err 终值 | **0.000** | 1.78 rad | 姿态收敛 |
| 力矩饱和占比 | **0.00%** | 17%（关节 2 全程顶限） | 不再顶满 |
| q_servo−q 漂移 RMS | **35.3 mrad**（max 213.8 / final 42.8） | 200–240 mrad | 降到 run_01 的 ~1/6 |
| 折叠特征（p_z 抬/塌） | **无**：p_z∈[0.335,0.363] 围绕 pd_z=0.35 | 抬至 0.70 后折叠 | 无向上抬、无折叠 |

**控制频率**（本次新测）：实测平均 **228.6 Hz**（中位 250 Hz），**61.7% 的控制周期超过
4 ms** —— 低于标称 250 Hz。这解释了残余漂移（q_servo−q RMS 35 mrad，虽仅 run_01 的
1/6 但非零）。

### RTDE 原始数据（独立来源，互证）
- **全程 44.3s `safety_mode` 恒为 1（REDUCED），无 2/3 跳变**：跟踪过程与后续保持
  （任务 18s 之后还有 26s）都**没有**发生保护性停止。用户观察到的"最后保护性停止"
  发生在按 Enter → `hw.shutdown()` → `servoStop()`/断开连接 的**关机环节**，不在跟踪内。
- `speed_scaling` 全程 1.0（100%），无降速。
- 折叠瞬间的电流尖峰（run_01 有 j1=4.6A）本次**不存在**。

### 运动学偏差（本次新发现，关键）
同一 home 位形下，模型 FK 与 RTDE 实测 TCP **不一致**：

| 来源 | home 位 TCP 位置 |
|---|---|
| 模型 FK(home_q)（`robot_model.get_frame_pose('tool0')`） | **(+0.350, 0.000, +0.350)** |
| 实机 RTDE 实测（`tcp_x/y/z`） | **(-0.350, 0.000, +0.224)** |

→ 实机 = 模型绕 z 转 180°（x 镜像）+ **z 整体低 0.126 m**。
RTDE 全程 TCP 范围 x∈[-0.451,-0.346]、z∈[0.210,0.238] 印证：臂实际在 **x<0 侧、
z≈0.22 m 高度**画圆（圆心 0.40→实机 -0.40、0.35→实机 0.224），比模型认为的 z=0.35
低了 12.6 cm。

### 仿真对照（理想闭环）
16s 整 4000 周期 @250 Hz，pos_err 终值 **0.000 m**、rot_err 0、积分漂移/饱和全 0，
判定"✓ 基本正常"——仿真仍是理想内层（无延迟/无限幅）。

## 5. 实验结论

1. **发散根因确认并已消除**：run_01 的 servoJ 级联失稳（带宽 10 下肘部力矩饱和 +
   参考积分漂移 → ~4.8s 外环发散 → 抬/折叠）在 `--bandwidth 6` 下完全消失。
   16s 完整跟踪、pos_err 终值 0.3 cm、力矩饱和 0%、无折叠特征。→ 根因确实是
   **高频任务下 servoJ 内层（增益式、无前馈、有延迟）追不上参考**，降带宽直接有效。

2. **REDUCED 安全模式不是发散主因（修正 run_01 结论）**：run_02 全程 `safety_mode=1`
   （REDUCED，未复位）依然全程稳定。run_01 记录中"REDUCED 是失稳重要推手"的判断
   被本次数据否定——REDUCED 只是状态异常，**发散由带宽/负载决定**。

3. **保护性停止发生在关机环节，不在跟踪过程**：RTDE 44.3s（含 18s 任务 + 26s 保持）
   全程 `safety_mode=1`，跟踪与保持阶段无任何保护性停止。用户看到的"最后保护性停止"
   是 `hw.shutdown()`（`servoStop`/断开）触发的，属释放/停机行为，不是控制失稳。

4. **控制频率低于标称**：实测平均 228.6 Hz（61.7% 周期 >4ms）< 标称 250 Hz。
   这是残余 q_servo−q 漂移（RMS 35 mrad）的来源，不影响稳定性但限制了精度上限。

5. **模型 FK 与实机坐标系存在固定偏差（新发现，最需要处理）**：
   实机 home TCP=(-0.350,0,0.224)，模型 (+0.350,0,0.350)——x 镜像（180° yaw）+ z 低
   0.126 m。后果：
   - 任务 `--center` 的 z 被实机执行**低 12.6 cm**、x 落在镜像侧；
   - `--preview` 的**碰撞判定用模型坐标系**，与实机空间不符（仿真认为离基座 0.35 m
     且高度 0.35，实机实际更低更近基座），可能漏报/误报真实碰撞风险。

## 6. 建议

1. **校基准（优先级最高）**：~~在 `se3_control/config/robot_configs.py` 给 UR3 加
   base 坐标系变换（R_yaw180° + z 平移 0.126 m，或等价标定 tool0 偏移），使
   模型 FK 与 RTDE 实测 TCP 对齐~~。**已完成（2026-08-11 校准）**：在 `ur3.urdf`
   的 `shoulder_pan_joint` 加基座 yaw180° + `flange-tool0` 沿 tool0 +z 偏移 0.126 m，
   FK(home_q) 现与 RTDE 一致 = (-0.350, 0.000, 0.224)。校准后任务坐标已换算
   （circle/line 圆心 `[-0.38,0,0.224]`），MuJoCo `--preview` site 同步到 tool0。
2. **控制频率**：实测平均 229 Hz 低于标称 250 Hz（61.7% 周期超 4ms）是残余漂移来源。
   排查 CB3 伺服循环负载/UR 内层协议开销；或把控制律 `dt` 与实测周期解耦。
3. **停机方式**：接受关机触发的保护性停止属正常；释放前先 `servoStop` + 操作者扶稳
   机械臂，避免在保持位形直接断开造成突然停止/抖动。
4. **复跑对照指标**：实机 `积分漂移 RMS`、`力矩饱和占比`、`误差发散`、`折叠特征`
   应保持本次水平（接近仿真）；残余漂移应主要由控制频率解释，而非饱和。
